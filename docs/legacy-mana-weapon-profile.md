# 全MPを威力へ変える武器57 v18

`legacy-mana-weapon-subset-v18` はMAGICAL武器57を追加する限定profile。
CLIの `mana-weapon` と `gv_*` は既存拡張も有効にし、187種・旧重み合計377で動く。
旧非公式エミュレーターを参考にしており、現行公式との完全一致は確認していない。

[追加魔法・MP消費順の調査](legacy-additional-magic-rules.md)、[台帳・出典・hash](../data/legacy-mana-weapon-v1/README.md)、
[前段の万能反射profile](legacy-any-reflection-profile.md)を参照。
既存17台帳を変更せず、追加1種を含むプール内で旧重みを正規化する。公式の配布率とは扱わない。

## 対象と威力

57は無属性のWEAPON。固定ATK・追加ATK・DEF・HP/MP増加の印字値は0、価格10・重み1。
使用時の現在MPを全量支払い、その2倍を基礎威力にする。保持化・奇跡取得・固定MP費用はない。

| 使用前MP | 基礎威力 | 使用後MP |
| --- | --- | --- |
| 0 | 0 | 0 |
| 3 | 6 | 0 |
| 10 | 20 | 0 |
| 99 | 198 | 0 |

攻撃のbaseとしてだけ使え、追加boostや回復としては使えず、武器なので捨てられない。
MP0でも武器所持と判定し、祈りを許可しない。威力0の攻撃を相手へ使うと通常どおり応答を待つ。
自分を対象にした場合は即解決する。威力0をパスや不正手へ置き換えない。

既存の普通boostを追加でき、支払MP×2に追加ATKを足す。
属性setter65/85も既存の火・水・無属性の到達結果を選べる。setter自体の追加ATKは旧規則どおり0。
57を使う行動と同時に選べるのはこの既存範囲の部品だけ。
有料の追加MAGIC、倍率214・全体化209、MP無料化MAGIC_FREEは対象外で、未対応IDを拒否する。
将来それらを導入する際は、魔法支払い後にMAGICAL威力を再設定する旧経路も合わせて扱う必要がある。

消費後に手札を詰め、消費枚数だけ配布予定を増やす。MP支払いそのものを追加の配布予定へ数えない。
すべての応答・反撃が終わってからまとめて補充する。満杯時も配布抽選は消費する。

## WEAPON由来と反応

名前にMAGICALを持つが、57はMAGICではなくWEAPONとして扱う。
無属性なら20/39・武器遮断215の対象となり、万能反射196は先頭使用なら属性を問わず使える。
魔法反射40/171/174/178や210の対象にはならない。
属性setterで有色にした場合、20/39・215は195の実選択など、既存の属性条件にも従う。

反射・跳ね返しは元の威力と支払MPを保持し、現在の相手MPから再計算しない。
MPをもう一度支払ったり、反射者の保持奇跡へ加えたりしない。
前置DEFによる減算は返却時に破棄され、195による属性消去は保持される既存規則を使う。
威力0でも反応でき、反応を使った分のカード消費・MP費用・配布予定を通常どおり処理する。

普通防御後のraw残余が正ならcounterを予約する。威力0や完全防御からcounterを生成しない。
新しいcounterは57の支払MP来歴を引き継がず、各counter自身の型・属性・倍率・対象方針を持つ。
193の自己MP回復が起動するのは元の57項目終了後であり、57の威力を変更しない。

## 上限と復元

`Config::mana_weapon` はデフォルトfalseで、他拡張を必須にはしない。
初期の中立環境だけに57を追加する構成も使える。

現在の普通boost最大値は15、57以外に選べる手札は最大15枚、MP上限は99。
従って最大raw威力は `99*2 + 15*15 = 423`。
既存の通常攻撃上限480、counterのint64威力上限・queue32枠を変更しない。
追加魔法や無料化を含む将来のプールへ、この上限を無検証で流用しない。

`Pending::mana_weapon=57` と `mana_spent` に、元の武器と使用時MPを記録する。
current57が未解決の間、元のturn_ownerのMPは0。このプールに、応答前置で元ownerのMPを回復する部品はない。
193等が元ownerのMPを増やす時点では、current57は既に終わり、この来歴を持たない別のcounter項目になっている。

Snapshot共通versionは37。同じビルド・Config内のfixture用で、旧形式を自動移行する永続checkpointではない。
57・damage・MP0の元owner・支払0〜99・元属性/setter・非MAGICを検証し、
`2*mana_spent <= amount <= 2*mana_spent+225` を要求する。
setterなしの有色化、奇跡・状態・命中・counter来歴との混在、counterへの支払来歴コピーを拒否する。
威力0のdamageを認めるのは正しい57来歴がある場合だけで、通常攻撃やcounterの正値条件は維持する。

## 観測・API

共通C++観測は1368次元、gv出力は先頭732次元。v18では末尾636特徴が0。guは先頭713、gz以前も従来の幅を維持する。
自分の手札の既存ATK欄は、57の場合だけ現在MP×2/30を返す。他のカードの特徴は変更しない。
同じ手札に残した別の57も、MPの増減に合わせてこの表示値が変わる。

| 位置 | 内容 |
| --- | --- |
| 713 | mana_weapon有効なら1 |
| 714〜729 | 自分の各手札位置が57なら1 |
| 730 | current項目が57由来なら1 |
| 731 | current57の支払MP / 99 |

追加19特徴は旧profileでは0。相手の未使用手札・完全な保持数・未来の抽選値・乱数状態は含めない。
手札のATKやraw威力の正規化は1を超え得るため、全特徴が0〜1とは仮定しない。

新C ABI [mana_weapon_c_api.h](../include/godfield/mana_weapon_c_api.h) は `gv_*` version18。
既存attack/setterの行動kindを使い、行動16byte・mask幅11・手札容量16を維持する。
57はMP0でもweapon_basesに含み、boost_slotsへは含めない。
構成した行動を `legal()` で検証する。C++ StepResultはmana_weapon_attack・mana_weapon_mp_spent・mana_weapon_powerを返す。
使用時に1回だけ記録し、後の反応やcounterの起動では再計上しない。

[Pythonラッパー](../python/mana_weapon_env.py)では `ManaWeaponBatchEnv` を使う。

```sh
python3 python/mana_weapon_env.py
./build/godfield_legacy_bench 100000 1 42 mana-weapon
./build/godfield_legacy_bench 100000 4 42 mana-weapon
```

全active行を事前検証して原子的に拒否する。終了行は固定・報酬0で不正手を無視し、自動resetしない。
報酬は固定座席順。Pythonの返却バッファーは再使用するので、履歴へ保存する際はコピーする。
同一ハンドルの同時操作はしない。既存gl〜gkは6byte、gx/gy/gz/guは16byteで各観測幅も維持する。

魔法遮断は[後段v19](legacy-magic-block-profile.md)で扱う。有料の追加MAGIC・倍率/全体化・MP無料化、霧188・幻覚189、忘却・守護神・蘇生・死亡時効果・終末・複数人戦、
旧版Pythonとの動的差分実行と現行公式照合、学習器・学習済みモデルは未対応。衝突C01〜C05も残す。

## 検証結果（2026-10-31）

通常CTest55件、ASan/UBSan37件、18種類のPython suite計166テストが通過。
最小ConfigのMP0応答・祈り/捨て禁止、動的ATKと全MP支払い、最大威力423、自己攻撃、
setter/boost・195、武器反応と魔法反応の型条件、反射後の支払来歴、counterへの非継承を検証した。
193による後続MP回復、Heavenの暫定HP0、威力0と不正snapshot、旧ABI出力境界、秘匿、1000試合replayも確認した。
通常配布で取得した57を手札に残し、206の初使用・保持再使用でMP10→5→0にしたPython局面でも、表示と0威力応答が正常だった。

全機能有効・10万試合・seed42・意思決定上限512で、1/4スレッドの全統計とchecksumが一致した。

MP0でもboostがあれば正の威力になるため、MP0と威力0の件数を区別する。
57の支払MPを奇跡のMP消費へ重ねて数えず、反射や後続counterでも再計上しない。
checksum v18は57の使用・支払MP・raw威力・対象/属性/選択部品と、pendingの新しい来歴を含める。
旧17profileのchecksum式を維持し、各10万試合で意思決定数・勝敗・draw・打ち切り・checksumが以前と一致した。
ASan/UBSanのベンチ1万試合でもReleaseの全統計とchecksumが一致した。
速度出力は行動生成・合法性検証・遷移・統計・resetを含み、観測転送・モデル推論を含まない。

共通観測の新しい追加部分は[HP吸収v28](legacy-hp-absorption-profile.md)を参照。旧ABIの幅・行動形式は維持する。
