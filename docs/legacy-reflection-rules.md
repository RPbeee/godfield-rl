# 旧版の反射・跳ね返し・遮断

調査日: 2026-10-31。Igoorxの非公式エミュレーターのソースを根拠とする。
これは現行公式の実測結果ではない。参照先の`master`は可変である。
今回の検討対象は物理神器による特殊応答で、魔法反射・反撃・状態異常・光闇は範囲外。

## 特殊効果が発火する入力

[turn.defenderCommand][turn]では、反応に使う神器の特殊効果と、元の行動の先頭神器の種別を調べる。
WEAPON系の特殊効果は元の先頭が武器の場合に発火するが、その後に属性等の追加検査がある。
候補ID20・39はいずれも無属性なので、そのままでは4属性攻撃を返せない。

| 入力 | REFLECT_WEAPON / FLICK_WEAPON / BLOCK_WEAPON | 先頭・単独のREFLECT_ANY |
| --- | --- | --- |
| 無属性の通常武器攻撃 | 属性も適合する無属性特殊神器なら対象になる | 対象になる |
| 火・水・木・土の武器攻撃 | 種別条件は満たすが、無属性特殊神器だけでは属性不適合 | 属性検査を迂回して発火 |
| 4属性の確率武器 | 命中後は武器の種別条件を満たす。ただし無属性特殊神器だけでは属性不適合 | 命中済み攻撃を返せる。命中再抽選はしない |
| 奇跡による攻撃 | WEAPON条件では発火しない。別のMAGIC系特殊効果の対象 | 発火する構造 |
| HP/MP回復の雑貨、HP/所持金回復の奇跡 | WEAPON条件では発火しない | 対象を入れ替えて効果を返す構造 |

ここでの表は特殊効果の分岐と検査についての記述。
種別不適合の神器を送信したとき、サーバーが必ず消費前に拒否することまでは意味しない。
旧版は分岐前に消費するので、不適合な選択が通常応答として消費される場合もある。
C++の合法手は、今回採用する意味的操作だけを許す方針で明示する。

REFLECT_ANYの属性検査迂回は、旧ソースが**選択列の最初の神器**を見て判定することに依存する。
通常防具の後ろへREFLECT_ANYを置いた場合へ、単独使用の結論を一般化しない。
反撃の先頭神器や闇に関する追加制限もあるが、今回の限定範囲では未対応のまま残す。
根拠: [turn.defenderCommandの特殊分岐・後段の検査][turn]、[Item.checkDefense][item]。

## 選択順・威力・消費

処理は反応の選択順に行う。通常防具も特殊神器も、その位置に到達した時点で使用・配布予定+1となる。
最初に発火した反射・跳ね返し・遮断でループを抜けるので、後ろの選択品は使われない。
従って、複数特殊をunordered maskで選び「全部消費」する実装は旧版と異なる。

さらに、通常防具による威力減算は応答用の複製に対して行う一方、
反射・跳ね返しは未減算の本体へ戻って攻撃元・対象を更新する。
そのため、先に使った通常防具は消費されても、返す攻撃の威力減算としては残らない。
反射神器自体に通常防御値があっても、特殊分岐で抜けるため、その位置の通常防御減算は行われない。
根拠: [turn.defenderCommand][turn]と[AttackData.clone][attack]。

| 例 | 旧版の結果 |
| --- | --- |
| ATK10に通常DEF3のみ | 残り威力7を受ける |
| ATK10にDEF3→反射 | 両方を消費。反射する威力は10 |
| ATK10に反射→DEF3 | 反射だけ消費。DEF3は手札に残る |
| 反射→別の反射 | 最初の反射だけ発火・消費 |

最初の実装を**特殊応答1枚単独**に制限すれば、既存の選択maskで順序の意味を失わず扱える。
これは意図したsubsetの制限であり、旧版の全ての複合応答に対応したという意味ではない。

## 攻撃元・対象と再応答

反射は現在の攻撃元と対象を入れ替える。通常手番の所有者は変更しない。
入れ替え後の対象が生存する他者なら、その人の応答へ進む。
跳ね返しは、現在の防御者を新しい攻撃元にし、新対象を生存者全員から無作為に選ぶ。
[room.getRandomAlive][room]は引数なしで呼ばれるため、元の防御者自身も候補である。

1対1で双方が生存する場合、跳ね返しは次の2通りになる。

| 新対象 | 処理 |
| --- | --- |
| 元の攻撃者 | 新しい防御応答を待つ |
| 跳ね返しを使用した本人 | 自分への効果を即解決。もう一度防御を選ぶ機会はない |

状態が生存者2人だけなら候補は等確率。チームや敵味方で候補を絞る呼び出しではない。
遮断は元の効果を適用せず、当該攻撃の解決を終える。
根拠: [turn.defenderCommand末尾][turn]、[room.getRandomAlive][room]。

## 確率・補充・再反射

反射・跳ね返しの再応答は`doAttack`を呼び直さず、`defenderCommand`へ進む。
従って、元の攻撃が確率攻撃でも、命中済みの攻撃に新たな命中抽選を行わない。
新しい攻撃キューへ同じ攻撃を投入し直す処理とも区別する。
最初の確率攻撃がmissなら、そもそも特殊応答を選ぶ機会がない。
根拠: [turn.doAttack / defenderCommand][turn]。

応答で実際に使用した神器分だけ配布予定が増え、連鎖中には配らない。
連鎖と手番末の処理を解決した後、生存者へ配る点は[room.endInning][room]と同じ。
旧版のこの経路に専用の「最大反射回数」検査は見つからなかった。
ただし今回の物理神器だけのsubsetでは再反射ごとに手札が消費され、補充もないので有限である。
学習用の意思決定上限で途中打ち切りにするなら、自然な解決とは別に記録する。

## 候補データと今回の範囲

値は[旧CSV][csv]からの候補。IDは旧行番号であり、現行公式IDとは扱わない。

| ID | 種別 | 通常攻撃値 | 特殊防御 | 今回の判断 |
| --- | --- | --- | --- | --- |
| 20 | 無属性WEAPON | 5 | FLICK_WEAPON | 無属性武器攻撃への単独跳ね返し候補。通常攻撃としての役割も残す |
| 39 | 無属性WEAPON | 10 | REFLECT_WEAPON | 無属性武器攻撃への単独反射候補 |
| 195 | 無属性PROTECTOR | なし | REMOVE_ATTRIBUTE | 反射ではない。攻撃本体の属性を無属性に変更する機能。複合応答の仕様として別扱い |
| 196 | 無属性PROTECTOR | なし | REFLECT_ANY | 単独なら4属性・確率攻撃を返す候補。回復・奇跡も返すなら元行動の種類を保持する必要がある |
| 215 | MAGIC | なし | BLOCK_WEAPON | MP6の防御用奇跡。既存の単純奇跡2種に含まれないため、物理反射対応へ黙って混ぜない |

ID195は攻撃の複製だけでなく本体の属性も変更するため、後に反射するならその変更は残る。
ただし特殊神器の後ろに195を置けば、先の特殊分岐で処理を抜けて195は未使用となる。
初期段階では195を除外するか、順序付き複合応答を別途設計する。

## 現在のsnapshot制約への影響

[legacy_env.cppのrestore](../src/legacy_env.cpp)は、反射前の単発応答を前提にしている。
以下は反射で到達可能な正当な状態を拒否するため、条件を単純に削除するのではなく、
元行動の情報と現在の解決情報を分けて検証し直す必要がある。

| 現在の前提 | 破れる例 |
| --- | --- |
| pending.sourceがturn_ownerと同じ | 防御者が反射すると、その防御者が現在のsourceになる |
| 応答中actorはturn_ownerではない | 元の通常行動者へ反射が戻ると、その人がactorになる |
| 応答対象の配布予定が0 | 元の行動者は最初の神器消費分の配布予定を既に持っている |
| sourceの配布予定数が、元の効果の使用枚数と一致 | sourceは特殊応答で入れ替わる。効果の支払者とは限らない |
| 各座席の配布予定は手札上限16以下 | 満杯の保持奇跡再使用で予定1を持ったまま反射を受け、その後手札16枚を応答に使うと予定17があり得る |
| 保持奇跡の所有者が現在のsource | REFLECT_ANYで奇跡を返すと、支払者と現在sourceが別になる |
| last_chanceのsource/targetが現在pendingと同じ | 命中イベントは元の攻撃時点。反射後の現在位置とは一致しない |

通常手番の所有者、元の使用者、現在の攻撃元、現在の対象、元神器の種類を分離して保持する。
公開した命中イベントの来歴も、現在のsource/targetへ上書きしてごまかさない。
消費・配布予定は各座席へ蓄積し、反射回数を理由に元の攻撃神器を再消費しない。

## 受入条件

1. 通常手番所有者を保ったまま、反射でsource/target・応答actorだけが入れ替わる。
2. 再反射でき、両者の配布予定が増えても復元・継続できる。
3. 跳ね返しの2候補を指定抽選で再現し、本人へ当たる場合は即解決する。
4. 元の命中抽選を追加消費せず、反射後の別actorで防御を継続する。
5. 武器反射の属性制限とANYの条件を区別し、許可しない組合せは消費前に拒否する。
6. 特殊1枚に限定する場合は、通常防具との混合や特殊複数を明示的に拒否する。
7. 連鎖中に補充せず、解決後に生存者へ各座席の予定数を配る。
