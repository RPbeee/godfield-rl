# MAGIC_FREEと順序付き無料化 v23

`legacy-magic-free-subset-v23` は正重量のMAGIC_FREE神器5種を扱う限定profile。
CLIの `magic-free` と `gi_*` は全拡張を有効にし、204種・旧重み合計395で動く。
現行公式の完全再現ではなく、旧非公式Flashサーバーを参考にした部分実装である。

[一次処理の調査](legacy-additional-magic-rules.md)、[台帳・出典・hash](../data/legacy-magic-free-v1/README.md)、
[前段の全体化奇跡profile](legacy-wide-miracles-profile.md)を参照。
既存22台帳のhashを固定し、対象プール内で旧重みを正規化する。公式の配布確率とは扱わない。

## 5種の神器と無料指定

| 旧ID / ローカルindex | 原典type | 通常の役割 | 旧価格 / 重み |
| --- | --- | --- | --- |
| 47 / 0 | WEAPON | 無属性ATK12 | 20 / 1 |
| 153 / 1 | PROTECTOR | 無属性DEF6 | 20 / 1 |
| 172 / 2 | PROTECTOR | 無属性DEF9 | 20 / 1 |
| 180 / 3 | PROTECTOR | 無属性DEF12 | 20 / 1 |
| 239 / 4 | SUNDRY | MAGIC_FREEだけ。単独使用不可 | 5 / 2 |

全て追加ATK・MP費用・命中率・病気/harms・他の特殊防御はない。47は捨てられず、他4種は捨てられる。
239のため `Kind::sundry=4` を末尾へ追加し、既存4値を保つ。HP/MP回復としては扱わない。
これらは普通神器であり、それ自体を奇跡として保持しない。

攻撃・防御の事前走査は、先頭以外で最初に見つけたFREEの**直前1品**だけを無料指定する。
直前のMAGICを探し直すことや、列中の全MAGICを無料にすることはしない。
MAGICの後に普通boostを挟めばそのboostが無料指定され、MAGICのMPは有料のままになる。
既にMAGICを使った後でFREEに到達すると、FREE自身を消費し配布予定+1を加えてから、
そのFREEのATK/DEF/属性処理を飛ばす。後置47のATK12を追加してはいけない。

先頭47だけを使えば通常の無属性ATK12武器。先頭のFREE効果で後ろのMAGICが自動無料になることはない。
無料のMAGICも初使用なら保持化し、保持からなら保持数を減らさず、各使用で配布予定+1を得る。
MP支払がない場合も、所有・順序・手札実体重複の検証は行う。

## 攻撃列と無料の単独奇跡

`attack_ordered`（kind11）は通常boost/setter、197/217、214、209とFREEを順序付きで扱う。
FREEは先行MAGICが必要で、％武器・MAGIC基底への自由追加にはしない。
最大65参照までとし、手札slot0〜15、保持197/217の16/17、214の18、209の19を維持する。
手札から初取得した奇跡を同列の後ろで保持として再使用できる。逆順やMP不足は原子的に拒否する。

新 `cast_ordered`（kind12）は既存の単独使用可能な奇跡へ、FREE手札1〜16枚を後置する。
baseは手札slot0〜15、保持197/217なら16/17、従来の通常保持15種なら32+iを使う。
手札の奇跡を基底にした場合はFREE最大15枚、保持基底なら最大16枚で配布予定17も扱う。
214/209は元々単独使用不可なので、このkindでも拒否する。
完成後はMAGIC由来のままで、相手への奇跡は通常防御・210・魔法反射/遮断・196の対象になる。
自分への単独使用は即解決し、追加の応答を作らない。

無料指定は各種効果の処理も変える。57基底では、有料MAGICはMPを払った後に残MP×2へ威力を再設定するが、
無料のMAGICはその再設定を行わず、現在の威力へ自身の加算・倍化・全体化を処理する。
例えば開始MP10の `57 → 197 → FREE` は無料197で20+2=22、57自身がMP10を消費する。
FREEを付けない `57 → 197` はMP2支払後に16へ再設定して+2=18となる。
MP台帳は追加ATK・倍化・全体化の実費と57自身の最終消費を別記録し、免除額とも区別する。

## 防御列と未消費suffix

新 `defend_ordered`（kind13）は、普通防具/反撃/FREEのprefix、発火する特殊1件、必要ならFREE suffix1枚の順を表す。
base/targetは255、slots/counter_count/counter_orderは0とし、extrasに全順序を入れる。
手札参照は0〜15、保持防御奇跡210/215は20/21。prefixの反撃予約順もextras順から作る。
特殊後の任意の未使用品列は省略し、FREE1枚以外の無意味なsuffixは拒否する。
Gloryの1枚制限は未消費suffixを含む選択参照数に対して検査する。

210/215の直後にFREEがあり、これが最初の後置FREEなら、その奇跡のMPを無料にする。
ただし210/215は特殊処理で途中終了するため、FREE suffixには到達せず**消費しない**。
初使用の奇跡は保持化し、保持からの無料応答も可能。prefixの消費・病気効果・配布予定は残る。
この挙動は239だけでなく47と3防具でも同じ。suffixを先に消費して有界にする変更は加えない。

先にprefixのFREEが無料指定を決めていた場合、後ろのsuffixはMPを免除しないが、特殊で未到達なら未消費のまま残る。
反射や遮断の後ろにもcanonicalなFREE suffixを置けるが、それらは元からMPを使わないので免除額は0。
反応の結果、元奇跡の費用・保持化・命中抽選を再実行しない。

無料の保持210はMPによる回数上限を持たない。決定上限による打ち切りと、uint64の配布予定/保持由来予定で扱う。
FREE有効時の保持由来予定は `decisions + 49`、観測の尺度は `max_decisions + 50`。
FREE無効の旧profileでは従来の上限49を維持する。これは旧serverの受理経路の再現で、公式UIの受理を確認した結果ではない。

## 上界・状態・観測

無料1回を含めて214は最大17回、209は最大20回、保持197は最大50回となり得る。
65参照で手札実体と保持反復を区別する。rawの保守的上界は `480 << 17`、32反撃までの保守的上界は `480 << 49`。
57の保守的上界は1194。開始MP99、57→有料214→+15を14枚→無料214→FREEで1164を作れるため、旧597では足りない。
費用免除で57の再設定も変わることを、単なるMP残量の違いに還元しない。

`Config::magic_free` はデフォルトfalseでadditive_miraclesを必要とする。
`AttackComposition` は65番目のIDと `held_tail` を追加し、先頭64件の保持maskはuint64のままにする。
`FreeCastComposition` に元奇跡・開始MP・保持由来・FREE16件の列を記録する。
Pending/LastReactionにもFREE来歴を持ち、復元時に順序と免除・消費を再検証する。
共通Snapshotはversion36。同じビルド・Config内のfixture用であり、旧形式の永続checkpoint移行はしない。

共通C++観測は1345次元、`gi_*` は先頭993次元。v23では末尾352特徴が0。旧 `gt_*` は945、gq以前も従来の出力幅を維持する。
v22では末尾400特徴が0。相手の未使用手札・非公開保持数・未来の抽選・乱数状態・fixture prefixは含めない。

## C ABI・Python

新C ABI [magic_free_c_api.h](../include/godfield/magic_free_c_api.h) は `gi_*` version23。
新 `gi_action` は88byteのままで、先頭prefixと64件のextras位置を保つ。
offset16はextra_count、17を65番目の `extra_tail` に使い、18〜23は予約0、24〜87は従来のextras64件。
extra_countが65未満ならextra_tailを0にする。旧APIでは最大64参照・65番目0を維持し、新kind12/13は渡さない。

mask幅は23。旧17語の位置を保ち、word17はFREE手札、18は無料cast可能な手札奇跡、
19は無料cast可能な従来の保持15種、20は保持197/217の2bit、21は無料防御の手札210/215、22は保持210/215の2bit。
maskは構成要素であり、MP・順序・隣接・同列取得・Glory等は `legal()` で全列を検証する。
予約byte・未使用参照・他kindの追加fieldは0にする。

[Pythonラッパー](../python/magic_free_env.py)は `MagicFreeBatchEnv` と最大65件の `Action.extras` を提供する。
batchは全active行を検証してから更新し、1行でも不正なら原子的に拒否する。
終了行は固定・報酬0で、不正手を無視し自動resetしない。報酬は固定座席順。
Python返却バッファーを保存するときはコピーし、同一ハンドルを同時操作しない。

```sh
python3 python/magic_free_env.py
./build/godfield_legacy_bench 100000 1 42 magic-free
./build/godfield_legacy_bench 100000 4 42 magic-free
```

霧/幻覚・忘却/守護神/蘇生・死亡時効果・終末・複数人戦、公式UIによる無料連鎖の受理、
現行公式との動的照合、学習器・学習済みモデルは未対応。衝突C01〜C05も残す。
受入検証は全5台帳の通常role、最初の隣接FREE、免除と実費、初使用保持化、未消費suffixと長い無料応答列、
57再設定/非再設定、65参照、復元・秘匿・旧ABI境界・batch原子性と旧22profile互換を対象とする。

## 検証結果（2026-10-31）

通常CTest71件、ASan/UBSan48件、23種類のPython suite計226テストが通過。
全5種の通常ATK/DEF/捨て可否、最初の隣接FREE、免除0と実費、初使用保持化、未消費suffix、
Gloryの選択枚数制限、57の無料時非再設定と大きな威力、65参照/tail、16枚FREE付き保持castを検証した。
実際に131,074回の無料応答を続け、保持由来予定が65,535を超えた状態の保存・復元と、
終端での大量配布・手札overflow時も抽選を消費することを確認した。
復元検査はMP差・反応回数の偶奇・195消費予算と大きなuint32反応回数も対象にする。
既存22profileは各10万試合で、従来の全156項目の決定的出力が基準と一致した。
