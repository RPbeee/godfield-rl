# 旧版の属性合成と防御判定

調査日: 2026-10-31。対象はIgoorxの非公式エミュレーター。
現行公式と旧版の光防御判定には[既知の衝突](official-spec-gap.md)があるため、
最初の属性対応は無属性と火・水・木・土に限定する。
以下はソース読解と合成規則の独立検算であり、公式画面から採取したfixtureではない。

## 結論

**通常の属性付き神器とINCREASE_ATKだけなら、追加神器の順序を持たないビットマスクで合成を再現できる。**
ただし、**ADD_ATTRIBUTEを含めると、光・闇を除いても順序依存になる。**
今回の台帳・合法手ではADD_ATTRIBUTE、倍率変更、全体化、反射等を除外し、対応対象を明示する。

## 通常の合成

攻撃側は[turn.queueAttackの末尾][turn]、防御側は[turn.defenderCommand][turn]に合成処理がある。
未選択の初期状態と無属性は別物。最初の神器で初期状態をその神器の属性へ変える。
以後、同じ属性は維持、異なる通常属性の混在は無属性にする。
光は通常の混在で代用属性として扱う。光しか選んでいないときだけ光のまま。

| 選択順 | 通常合成の最終属性 | 注意 |
| --- | --- | --- |
| 無属性、火 | 無属性 | 最初の無属性は「まだ属性がない」状態ではない |
| 火、無属性の攻撃追加 | 無属性 | 無属性の追加分を属性計算から除外しない |
| 火、火 | 火 | 威力だけ加算 |
| 火、水 | 無属性 | 同じ神器を逆順にしても無属性 |
| 火、水、火 | 無属性 | いったん混在した後の通常追加で火へ戻らない |
| 光、火 ／ 火、光 | 火 | 通常合成では順序不変 |
| 光、無属性 ／ 無属性、光 | 無属性 | 光が無属性を火等へ変えるわけではない |
| 光、光 | 光 | 光のみの合成は光 |
| 火、水、光 | 無属性 | 光追加で混在が解消するわけではない |

同じ通常規則は防御側にも当てはまる。
通常属性だけなら、光以外の属性が1種類だけの集合はその属性、
光以外が複数種類なら無属性、全て光なら光、と整理できる。
ここで無属性も「光以外の1種類」として数える。

独立した小さな検算で、無属性・4属性・光の全組み合わせ（長さ1〜4）の順列19,374通りを確認し、
通常合成の順序不変を確かめた。この検算は合成の数学的な性質についての検証であり、
実ゲームの仕様や旧ソース実行結果と一致すること自体の証明ではない。

## ADD_ATTRIBUTEは別の処理

攻撃側はADD_ATTRIBUTEを見た位置で、それまでの合成結果を当該神器の属性へ上書きする。
[CSV][csv]ではID65が火、ID85が水のADD_ATTRIBUTEを持つ。

| 同じ先頭と追加集合を使う例 | 最終属性 |
| --- | --- |
| 火の基底 → 水ADD_ATTRIBUTE → 無属性INCREASE_ATK | 無属性 |
| 火の基底 → 無属性INCREASE_ATK → 水ADD_ATTRIBUTE | 水 |
| 火の基底 → 火ADD_ATTRIBUTE → 水ADD_ATTRIBUTE | 水 |
| 火の基底 → 水ADD_ATTRIBUTE → 火ADD_ATTRIBUTE | 火 |

したがって、混在で無属性になった後でも、明示的なADD_ATTRIBUTEなら属性を復活させられる。
INCREASE_ATKと同じ扱いにはできない。これらを同じunordered maskで許可して
スロット昇順で処理すると、ユーザーが選べる順序を一部失った環境になる。
将来対応する際は、順序付き追加列などの行動表現が必要。

## 防御は最後の合成属性で判定

通常防御では、選択列から防御値を差し引きながら防御属性を合成し、
最後に[Item.checkDefense][item]で攻撃属性と**最終防御属性**を照合する。
各神器を別々に適合判定して、防御値だけ都合よく合計する処理ではない。
防御値を十分に積んでも属性が不適合なら、その選択を合法化しない。

| 攻撃 | 今回の限定範囲で適合する防御属性 |
| --- | --- |
| 無属性 | 無属性・火・水・木・土 |
| 火 | 水 |
| 水 | 火 |
| 木 | 土 |
| 土 | 木 |

空の防御は選択品なしで受ける経路であり、「未選択属性と攻撃属性を照合して拒否する」とはしない。
例えば火攻撃に水防具だけなら適合し、水防具と無属性防具を同時に使うと最終無属性となり不適合。
無属性攻撃には防具の混合で最終無属性になっても適合する。
特殊防御は通常処理とは別に分岐するので、ここでの規則を反射・跳ね返しへ一般化しない。

旧版の属性表は4属性に光の代用を加え、光攻撃には闇防御を許すが、
現行抽出記録は光への防御不可とする。この衝突は未解消のまま残す。
今回の限定範囲から光・闇を除くことで、この衝突を処理対象へ持ち込まずに済む。
「現行の光・闇へ対応した」という意味ではない。

## 実装上の受入条件

1. 台帳の属性を種別・威力とは別に保持し、未対応効果の神器を黙って通常神器へ変換しない。
2. 基底属性を最初に入れ、追加INCREASE_ATKの属性も含めて合成する。
3. 同じ追加集合の順序を変えても同じ結果になるのは、今回許可した効果範囲だけとする。
4. 火攻撃に対する水＋無属性防具のような、不適合の最終合成を合法手検証で拒否する。
5. 0枚の防御は受け入れ、属性不適合の選択は消費・配布予定・乱数を変えずに拒否する。
6. 既存profileの無属性データと観測寸法を維持し、属性追加は別profile/schemaとして扱う。
