# 保持の忘却 v24

`legacy-forgetting-subset-v24` はSUNDRY241のREMOVE_ABILITIESを扱う限定profile。
CLIの `forgetting` と `gj_*` は全拡張を有効にし、205種・旧重み合計398で動く。
現行公式の完全再現ではなく、旧非公式Flashサーバーを参考にした部分実装である。

[台帳・出典・hash](../data/legacy-forgetting-v1/README.md)、
[従来の保持表現](legacy-miracles-rules.md)、[前段のMP無料化profile](legacy-magic-free-profile.md)を参照。
既存23台帳のhashと全ての保持ローカルindexを固定し、対象プール内で旧重みを正規化する。
公式の配布確率とは扱わない。

## 241の単独使用と防御

| 旧ID / ローカルindex | 原典type / 効果 | 値 | MP | 旧価格 / 重み |
| --- | --- | --- | --- | --- |
| 241 / 0 | SUNDRY / REMOVE_ABILITIES | 保持コピー1個を忘れる | 0 | 10 / 3 |

普通ATK・追加ATK・DEF・HP/MP変化、病気/harms、他の特殊防御はない。捨てられる普通神器であり、奇跡として保持しない。
重み0のCREATURE250は対象プールへ入れない。手札の `use`（kind3）で使い、相手か自分を指定する。
単独使用だけを認め、追加武器・無料cast・保持castにはできない。
手札241を消費して配布予定+1を処理する。自分への使用は即解決し、相手への使用には応答がある。
対象の保持が空でも使用でき、その場合は何も失わない。

CSV属性列は空だが、旧queueAttackはこの効果で途中終了し、属性を代入しない。
そのため実payloadは普通の無属性ではなく **None**。コアは `Element::none=7` と専用Effectで区別する。
普通防具と195は使えず、武器/MAGIC専用の反射・遮断・210/215も対象外。
先頭196だけは属性検査を省略するため反射できる。196より前のprefix防具を許可する通常経路には戻さない。
反射後は現在のtargetから抽選し、元の使用者に忘却が返る場合もある。
MP無料化profileの後置FREE suffixは、先頭196という条件を変えずに未消費で残せる。

## コピー数に比例する抽選

解決時点の対象の保持21種を合計し、重複したコピーを等確率で選んで1個だけ減らす。
型ごとの一様抽選や、その型の全コピー削除にはしない。
例えば197を3個、216を1個持つ対象では、197が3/4、216が1/4になる。
通常15種・防御2種・追加ATK2種・倍化1種・全体化1種を全て対象とする。
最後のコピーを失えば対応する保持maskが消え、同種を手札から使い直せば再び保持できる。

`retained_type_ids` は次の昇順21種で、各familyの既存indexとは独立した抽選順である。

```text
197 198 199 200 203 204 205 206 207 209 210
214 215 216 217 218 219 220 222 223 226
```

非空の対象では、保持が1個だけでも抽選用の乱数またはfixture ticketを1件消費する。
空なら消費しない。`script_forget_tickets` はuint64のprefixを与え、その時点の総コピー数で剰余を取ってrankにする。
prefixを使い切った後はseed付き抽選へ戻る。不正なfixture置換は状態を変えない。

旧Pythonは取得順の保持リストからrandom.choiceし、選ばれたIDの最初のコピーをlist.removeする。
この環境のID昇順・コピー数加重rankは確率分布を再現するが、その取得順やPythonの乱数bit消費、
seedから選択IDへの対応、XMLの個体indexまでは再現しない。この差を現在公式との一致とは扱わない。

## 状態・観測

`Config::forgetting` はデフォルトfalseでmiraclesを必要とする。他の拡張は任意。
`Pending::forget_card` が元神器241を表し、現在source/targetと反射前の所有者を区別する。
`State::last_forget` に神器ID・source・target・削除ID・削除前総コピー数を記録する。
空の試行も記録するが、削除前総数は非公開の内部値である。
共通Snapshotはversion36。同じビルド・Config内のfixture用であり、旧形式の永続checkpoint移行はしない。

共通C++観測は1345次元、`gj_*` は先頭1017次元。v24では末尾328特徴が0。旧 `gi_*` は993、gt以前も従来の出力幅を維持する。
v23では末尾352特徴が0。相手の残り保持数、抽選ticket、乱数状態、未来の抽選・fixture prefixは含めない。
公開するのは忘却試行のsource/targetと、失ったIDまたは空だったことだけである。

| 位置 | 内容 |
| --- | --- |
| 993 | forgetting有効なら1 |
| 994〜1009 | 自分の手札が241なら1、その他0 |
| 1010 | 現在の保留itemが忘却なら1 |
| 1011 | 最後の忘却試行があれば1 |
| 1012 | 最後のsourceが自分なら1 |
| 1013 | 最後のtargetが自分なら1 |
| 1014 | 最後に失ったID / 363、空なら0 |
| 1015 | 最後にコピーを1個失ったなら1 |
| 1016 | 自分の現在の総保持数 / `16 * max_decisions` |

旧特徴位置・保持indexを移動せず、保持の観測は忘却後の在庫を返す。
累積学習数は在庫と区別し、`累積学習 = 現在の保持 + 忘れたコピー数` で検証する。

## C ABI・Python

新C ABI [forgetting_c_api.h](../include/godfield/forgetting_c_api.h) は `gj_*` version24。
`gj_action` はgiと同じ88byte、kind0〜13、最大65参照とextra_tail@17を維持する。
忘却は既存useだけを使い、新しいaction kindや保持slotは追加しない。
mask幅は24。旧23語の位置を保ち、word23は241の手札slotを表す。複合条件は `legal()` で検証する。
予約byte・未使用参照・他kindの追加fieldは0にする。

[Pythonラッパー](../python/forgetting_env.py)は `ForgettingBatchEnv` と忘却ticket fixtureを提供する。
batchは全active行を検証してから更新し、1行でも不正なら原子的に拒否する。
終了行は固定・報酬0で、不正手を無視し自動resetしない。報酬は固定座席順。
Python返却バッファーを保存するときはコピーし、同一ハンドルを同時操作しない。

```sh
python3 python/forgetting_env.py
./build/godfield_legacy_bench 100000 1 42 forgetting
./build/godfield_legacy_bench 100000 4 42 forgetting
```

霧/幻覚・守護神/蘇生・死亡時効果・終末・複数人戦、旧Pythonの取得順/個体index再現、
公式UIによる無料連鎖の受理、現行公式との動的照合、学習器・学習済みモデルは未対応。衝突C01〜C05も残す。
受入検証は21種のコピー削除、加重rank/空/1個での抽選消費、自己使用・196反射とNone防御境界、
保持maskの消失/再取得、在庫収支、復元・秘匿・旧ABI境界・batch原子性と旧23profile互換を対象とする。

## 検証結果（2026-10-31）

通常CTest74件、ASan/UBSan50件、24種類のPython suite計238テストが通過。
21種の削除と最後のコピーのmask消失、コピー数加重rank、空/1個での抽選消費、自己使用と196反射、
None防御・195拒否、保持の再取得、population秘匿、snapshot/ticket復元、batch原子性と旧ABI境界を検証した。
既存23profileは各10万試合で、従来の全167項目の決定的出力が基準と一致した。
