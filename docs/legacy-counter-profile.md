# 土の反撃と項目キュー v13

`legacy-counter-subset-v13` は土の反撃防具190と、効果項目ごとの死亡確定・反撃キューを追加する限定profile。
CLIの `counter` と `gk_*` はv13までの拡張を有効にし、176種・旧重み合計366で動く。
旧非公式エミュレーターを参考にした実装で、現行公式の完全再現ではない。

## 対象と採用した規則

[旧版の反撃処理](legacy-counter-rules.md)、[台帳・出典・指紋](../data/legacy-counter-v1/README.md)を参照。
既存12台帳を変更せず、限定プール内で旧重みを正規化する。公式の配布率とは扱わない。

| 旧ID | 種類 | 防御属性 | 通常DEF | 反撃 | MP | 旧価格 / 重み |
| --- | --- | --- | --- | --- | --- | --- |
| 190 | COUNTER防具 | 土 | 0 | 防御後の残余ダメージ×2、土の確定攻撃 | 0 | 10 / 1 |

190は武器・奇跡ではなく、捨てられる防具。通常手番の攻撃や追加ATKには使えない。
187火確率、188霧、189幻覚、191Glory、192DarkCloud、193MP、194所持金の反撃はv13には含めない。
187/191/192/193と混合順序は[反撃拡張v14](legacy-counter-extensions-profile.md)で追加する。
異なる種類の反撃を混ぜるとキュー順で効果が変わるため、まず同種190だけで状態遷移を実装する。
同じIDの別個体を複数選ぶことはでき、生成する反撃は同じ威力・source/targetなので順序は同値。

**反撃への防御は旧serverの受理挙動を採用する。** 普通防具・195・さらに190を使える。
旧botは反撃に防御を返さないため、[衝突C05](official-spec-gap.md)として区別する。
どちらが現行公式に一致するかは未確認で、bot意図や現行ルールを確定した実装とは扱わない。
Gloryの1枚制限については既存profileと同じ旧bot由来の意図規則を維持する。

## 防御・予約・元ダメージ

190はdefend/defend_castのslotsへ普通防具の前置と同じように入れる。baseの特殊応答ではない。
選択時に消費し、1枚ごとに配布予定+1。土属性も最終防御合成へ参加する。
普通防具の減算後、残余が正なら各190から2倍の反撃をFIFOへ予約し、その後に元の攻撃を適用する。
残余0なら消費だけで発動しない。非damageへの使用でも消費だけになる。
反射・跳ね返し・遮断が発火した応答では、前置190は消費するが反撃を予約しない。
Gloryでは190も1枚に数える。

倍率の基準はraw残余であり、実HP損失ではない。
HP1で残余10を受けても反撃は20。闇の残余5なら反撃10で、闇の999処理を倍にしない。
元の被弾Gloryや病気でHP0となっても、予約済みの威力は残る。
反撃は新しい土の攻撃で、元のmiracle・hit_rate・病気・Glory・属性付け替え/消去を引き継がない。
195を元攻撃に使っても、生成される190の属性は土。

## キュー・死亡・再防御

元効果の解決後にHP0を死亡確定し、次の予約項目を取り出す。
sourceが既に死亡していても予約済みの反撃は実行する。targetが死亡済みならその項目を飛ばす。
反撃の使用時に増やした配布予定を、起動時にもう一度増やしたりカードを再消費したりしない。
後からGloryを付けられても、既に予約した複数項目を削らない。

反撃には普通防具で応答でき、195で無属性化して防ぐこともできる。
さらに190で返す場合は新しい反撃をキュー末尾へ加え、先に予約済みの項目を追い越さない。
195を使ってもCOUNTERという由来は残り、20/39・210・215では返したり遮断したりできない。
これらの特殊条件を単なるdamage/NE判定へ置き換えない。

HP0と死亡確定は別に持つ。現在の効果の途中では、既存のHeaven前置から回復・反応で救済される経路を維持する。
ただし、項目終了時に死亡確定した人物を後の通常行動者や反撃の防御者にはしない。
全キューが終わってから元のturn_ownerの病気tickを1回だけ処理し、死亡を再確認して生存者へまとめて配る。
勝敗もその後に確定する。両者死亡は `terminated=true, winner=-1, rewards=[0,0]` という学習規約で表す。
反撃だけでも両者死亡は起こるので、disease無効の構成でもこの終局を扱う。

## 固定容量・整数・復元

補充まで新しい手札は入らず、両者の手札は各16枚。保持奇跡で始めると元行動で手札を減らさない場合もあるため、
生成する反撃の総数上限は32とし、固定長 `Pending[32]` を使う。恣意的な反撃回数制限は追加しない。
`counter_generated == counter_started + counter_count` を保ち、dead targetのskipもstartedへ数える。
キュー未使用領域はPendingの初期値へ戻す。

再反撃で威力が増幅するため、`Pending::amount` はint64へ広げる。
原攻撃の保守上限480と生成総数32から、反撃の保守上限は `480LL << 32`。
復元時は生成数に応じた `480LL << counter_generated`、正値・2の倍数、190/土の来歴を検証する。
HPは64bitで減算して0〜99へ収める。
元攻撃のmiracle所有者はturn_ownerのままだが、反撃の所有者は使用した防御者。
`Pending::origin_source` と `counter_card` を持たせて、手番所有者と項目の由来を混同しない。

Snapshotはキュー件数・来歴・source/target・未使用tail・消費済み手札による配布予算・dead/HPの整合を検査する。
完了していない反撃が消費枚数より多いsnapshotや、counterを武器反射へ変換したsnapshotは拒否する。
打ち切り時は未解決キューを残してtruncatedとし、自動resetしない。

## C++・観測・API

```cpp
godfield::legacy::Env env({512, 10, true, true, true, true, true, true, true, true, true, true, true, true});
env.reset(42);
```

末尾の `Config::counters` はデフォルトfalseで、elementsを必要とする。他の拡張は個別に選べる。
既存profileではdead/queue/originの新しい状態を無効時の初期値に保ち、元の遷移を維持する。
`Options::counter_slots` は190の手札候補maskで、最終属性やGloryによる合法性は `legal()` でも検証する。
`StepResult::counter_queued/counter_launched/counter_skipped/counter_resolved` は当該stepのキュー処理を表す。
Snapshotの共通versionは36。同じビルド・設定のfixture用で、旧形式を自動移行する永続checkpointではない。

共通C++観測は1345次元、`gk_*` ABI 13は先頭515次元を返す。v13では末尾830個は0。先頭393個は[属性消去profile](legacy-attribute-removal-profile.md)を継承する。

| 位置 | 内容 |
| --- | --- |
| 393 | counters有効なら1 |
| 394〜409 | 自分の各手札位置が190なら1 |
| 410 | 未解決counter_card / 363 |
| 411 | 未解決項目のorigin_sourceが現在actorなら1 |
| 412〜413 | 自分 / 相手の死亡確定flag |
| 414〜416 | queue件数 / 生成済み / 起動済み。それぞれ32で割る |
| 417 | 未解決項目が反撃なら1 |
| 418 | 未解決反撃のamount / counter_damage_limit |
| 419〜514 | 公開済みqueue32枠×3値。source==actor、target==actor、amount/480。空きは0 |

原攻撃とqueueのamount/480は1を超え得る。全観測が0〜1という仮定は置かない。
公開済みの予約だけを観測し、相手の未使用手札・完全な保持数・未来の抽選値・乱数状態は含めない。
旧profileの追加122特徴は0。

[counter_c_api.h](../include/godfield/counter_c_api.h) の `gk_*` と[CounterBatchEnv](../python/counter_env.py)を使う。
6byteの `gl_action` とkind0〜9を維持し、mask幅11の最後にcounter_slotsを追加する。
旧 `gl/gm/ge/gc/gr/gd/gh/gs/go/gb/ga/gn` の128/164/186/210/236/258/283/301/334/356/375/393次元とmask幅は維持する。
固定座席報酬、バッチの原子的拒否、終了行固定・自動resetなしを継承する。
Pythonバッファーは再使用するので、履歴へ保存する際はコピーする。同じハンドルを複数スレッドから同時操作しない。

```sh
python3 python/counter_env.py
./build/godfield_legacy_bench 100000 1 42 counter
./build/godfield_legacy_bench 100000 4 42 counter
```

v13では他7種類の反撃と異種反撃の順序は対象外。v14でも188/189/194、万能反射、追加魔法、霧・幻覚、守護神、蘇生、死亡時攻撃、終末、複数人戦、
現行公式との動的照合と学習器は未対応。資料間衝突C01〜C05を残す。

## 検証結果（2026-10-31）

通常CTest 40件、ASan/UBSan 27件が通過。新旧13種類のPython suiteは計109テスト。
raw残余倍率・低HPclip、同190複数と世代の混在するFIFO、特殊前置/非damage時の不発、
死者source・死亡target skip・病気なしの両死draw、owner tick1回、自然な反撃510、int64上限、
queue/origin/tailの不正復元拒否、未解決打ち切り、秘匿、1000試合の再現を確認した。

全機能有効・10万試合・seed42・意思決定上限512で、1/4スレッドの統計とchecksumが一致した。

| 項目 | 値 |
| --- | --- |
| 意思決定数 | 3,377,282 |
| 座席0 / 座席1勝利 | 49,803 / 49,550 |
| 勝者なし / 打ち切り | 647 / 0 |
| 反撃予約 / 起動 / 死亡対象のskip | 3,098 / 3,097 / 1 |
| 反撃の解決 / 反撃への防御決定 | 3,097 / 3,097 |
| 190消費枚数 | 4,714 |
| 未処理キュー / 未解決反撃 | 0 / 0 |
| checksum v13 | 8854737823814738813 |

予約されなかった190も消費枚数に含む。キュー起動とカード消費を二重計上しない。
元奇跡が終わって次のcounter応答へ移る場合も、元奇跡の解決を集計し、病気tickをそのHP変化から分離する。
ベンチの速度出力は行動生成・合法性検証・遷移・統計・resetを含み、観測転送・モデル推論は含まない。
旧12profileのchecksum式を維持し、同条件の各10万試合で意思決定数・勝敗・checksumが以前と一致した。

共通観測の新しい追加部分は[HP吸収v28](legacy-hp-absorption-profile.md)を参照。旧ABIの幅・行動形式は維持する。
